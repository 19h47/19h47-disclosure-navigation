Disclosure Navigation

Keyboard support and open/close state for a site navigation built on the WAI-ARIA disclosure navigation pattern. You write the HTML, the library enhances it. The navigation at the top of this page uses it.

Navigation, not a menu

A site navigation is a list of links. Buttons announce collapsed or expanded, links stay links. The ARIA menu role is meant for application menus and changes how screen readers read the page.

Your HTML is the source of truth

The library reads aria-expanded and aria-controls, and never adds a missing attribute. The state stays in the DOM, where CSS, tests and other scripts can read it.

Built on the platform

Native <button> for Enter and Space, the hidden attribute, ariaControlsElements to find submenus, AbortController to clean up.

Small and typed

About 1 kB gzipped, no dependency, TypeScript declarations and typed events included.

Usage

npm install @19h47/disclosure-navigation
import DisclosureNavigation from '@19h47/disclosure-navigation';

const $nav = document.querySelector('.disclosure-nav');
const disclosureNavigation = new DisclosureNavigation($nav);

disclosureNavigation.init();

init() only adds listeners: the markup is left as you wrote it. destroy() removes them.

Playground

Use the mouse or the keyboard, then change the options. Every event the library fires shows up in the log.

    Markup

    Follow the APG structure: a <nav> with a list, a button per submenu, and the submenu it controls. 

    <nav class="disclosure-nav" aria-label="Main">
	<ul>
		<li><a href="/">Home</a></li>
		<li>
			<button type="button" aria-expanded="false" aria-controls="about-menu">
				About
			</button>
			<ul id="about-menu" hidden>
				<li><a href="/about/overview">Overview</a></li>
				<li><a href="/about/team" aria-current="page">Team</a></li>
			</ul>
		</li>
	</ul>
</nav>
    Attribute On Role
    aria-label <nav> Names the landmark when the page has more than one navigation.
    aria-expanded <button> The state. A button without it is ignored. The library updates it.
    aria-controls <button> ID(s) of the submenu(s), inside the navigation. Several IDs are shown and hidden together.
    hidden Submenu Present while collapsed. The library updates it, and it keeps hidden links out of the tab order.
    aria-current <a> Optional: marks the current page.

    State comes from the HTML

    Render the current section open: write aria-expanded="true" and leave out hidden. The library starts from there. This sidebar is the same library with a vertical layout and a nested submenu.

    Nested submenus

    A submenu can hold buttons with their own submenus, like More in the sidebar. Opening one keeps its parents open and closes the other branches. Closing a submenu closes the ones nested in it. Arrow keys move within one level, ↓ on an expanded button enters its submenu, and Escape closes the innermost one.

    Styling

    Style the state the library writes: aria-expanded on the button, hidden on the submenu. Transitions on hidden use @starting-style to open and a display transition to close. Browsers without the display transition (Firefox) close instantly. 

    button[aria-expanded="true"]::after {
	rotate: 225deg;
}

.disclosure-nav__menu {
	transition: opacity 0.15s, translate 0.15s, display 0.15s allow-discrete;
}

.disclosure-nav__menu[hidden] {
	opacity: 0;
	translate: 0 -0.25rem;
}

@starting-style {
	.disclosure-nav__menu {
		opacity: 0;
		translate: 0 -0.25rem;
	}
}

@media (prefers-reduced-motion: reduce) {
	.disclosure-nav__menu {
		transition: none;
	}
}

    If your CSS gives the submenu a display value, restore [hidden]:not([hidden="until-found"]) { display: none; } for it. Use logical properties such as inset-inline-start to position submenus: they then follow the reading direction.

    Keyboard

    Key Focus on Action
    Tab / Shift + Tab Anywhere Native order. Collapsed submenus are skipped.
    Enter / Space Button Toggles its submenu (native button activation).
    Escape Button or top-level link Closes the open submenu.
    Escape Submenu Closes the innermost one and moves focus back to its button.
    ↓ Expanded button, at any level Moves focus to the first item of its submenu.
    ← → ↑ ↓ Top-level item Previous or next button or link, wrapping.
    ← → ↑ ↓ Submenu item Previous or next item, wrapping.
    Home / End Top-level or submenu item First or last item.

    Arrow keys are optional in the APG pattern: set useArrowKeys = false to keep Tab only. Keys pressed with Alt, Ctrl or ⌘ are left to the browser, and so are arrow keys in a text field. Moving focus out of the navigation closes the open submenu.

    In a right-to-left context, ← and → swap. The library reads the direction from the markup with :dir(rtl), so a dir attribute on the page or the navigation is enough: try it in the playground.

    In a dialog or a popover

    Escape is also a close request: it closes the topmost dialog or popover. While a submenu is open, the library cancels the key press, so each press closes one layer: the submenu, then the dialog. With every submenu closed, the browser handles the key.

    Find in page

    Write hidden="until-found" on collapsed submenus and their links stay searchable. When find in page (Ctrl + F or ⌘ + F) or a link to a fragment reveals a submenu, the library opens it, nested ones included, and keeps until-found when it closes again.

      Events

      Events fire on the button before the DOM changes and bubble, so one listener on the navigation is enough. Call preventDefault() to cancel the change.

      Event Detail
      disclosure-navigation:open { $button, elements }
      disclosure-navigation:close { $button, elements } 
      $nav.addEventListener('disclosure-navigation:open', event => {
	const { $button, elements } = event.detail;

	if ('services' === $button.id) {
		event.preventDefault(); // Services stays closed
	}
});

      In TypeScript, both events are declared on HTMLElementEventMap: event.detail is typed.

      API

      Member Description
      new DisclosureNavigation($nav) $nav is the navigation. Buttons are found inside it with button[aria-expanded][aria-controls].
      $el The navigation passed to the constructor.
      init() Listens to click, keydown and focusout on $nav. Call destroy() before calling it again.
      destroy() Removes the listeners. The markup stays in its current state.
      open($button) Closes the open submenu, then opens the one of $button.
      close($button?) Closes the submenu of $button, or every open submenu. Focus inside a closing submenu moves to its button.
      toggle($button) Opens or closes the submenu of $button.
      useArrowKeys Enables arrow, Home and End keys. Defaults to true.

      Buttons are read from the DOM on each interaction, so adding or removing items needs no call. Closing the submenu once a link is followed is up to you, as in the header of this page: 

      $nav.addEventListener('click', event => {
	if (event.target.closest('a')) {
		disclosureNavigation.close();
	}
});

      Closing from outside

      The open submenu closes when focus leaves the navigation. Safari does not focus a button on click, by design: after opening a submenu with the mouse, clicking elsewhere moves no focus and the submenu stays open. If you need it, close it yourself: 

      document.addEventListener('click', event => {
	if (!$nav.contains(event.target)) {
		disclosureNavigation.close();
	}
});

      Browser support

      Submenus are resolved with ariaControlsElements: Chrome and Edge 135, Firefox 136, Safari 16.4. For older browsers, load a polyfill of ARIA element reflection for ariaControlsElements, or use another library.

      Find in page relies on hidden="until-found": Chrome and Edge 102, Firefox 139, Safari 26.2. Elsewhere it acts as hidden. The library ships as an ES module.
